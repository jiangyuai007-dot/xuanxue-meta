## 二、还缺什么功能

### 必须修（上线前）

**F-1 「追问 3 次」是虚假商品（P0）**
`full_plus` SKU（¥29.9）写着「全部章节 + 3 次针对本命盘的追问」，但我盘点前后端：**追问功能完全不存在**（前端 0 处实现、后端无对应接口）。用户付了钱拿不到承诺的东西，直接构成交易纠纷。两个选择：
- 立即下架该 SKU（最小改动，本报告推荐）；
- 或实现追问功能（成本：前端输入界面 + 后端限额扣次 + 解读生成）。

**F-2 支付弹层字数显示为 0（P1）**
实测弹层显示「约 0 字 · 解锁后完整可读」——字数统计没取到值。小 bug 但出现在付费决策的关键位置，影响信任。

**F-3 真实支付渠道（P0，收费上线硬前提）**
`payOrder` 仍是模拟支付（点了就直接变已支付）。要收钱必须接微信/支付宝，含回调验签、幂等、对账、退款。这是外部的商务+开发工作，不是今天能代码修完的。

### 应该有（上线后尽快）

- **账号体系 / 跨设备同步**：权益凭证存在浏览器本地，换设备或清缓存即丢已购。月卡 SKU 已有订阅语义，但没有登录就谈不上会员。
- **订单中心页**：现在只有「我的已购」弹层，用户看不到自己的订单列表/状态/退款入口（协议里承诺了退款路径，却没有自助入口）。
- **会员月卡购买入口核对**：SKU 表里有 member_month，前端列表是否展示并正确计价，需人工点一遍（未纳入本次自动化）。
- 内容纵深：每日一签、合盘、流月流日下钻（已有基建，未串联成入口）。
