## 1. 项目目标与最小可用范围

### 1.1 目标

交付一个**可本地启动、核心主流程完整可跑通**的命理内容产品原型：

1. 用户输入生辰/问题 → 系统产出**结构化命盘事实包** → 生成**可读报告** → 浏览器可查看、可导出、可分享。
2. 全程**零外部依赖、零网络调用**（不调用任何 LLM API、不联网），保证离线可复现、可测试。
3. 合规网关内建在生成链路中，任何输出都经过断言检测与免责声明注入。

- 不做"改运/化解"类付费（合规红线）
- 不做医疗、投资、法律类结论

## 2. 技术选型与理由

| 选择 | 内容 | 理由 |
|---|---|---|
| 运行时 | **Node.js 22（原生，零第三方依赖）** | 本机 npm 网络与可用性不确定；原生 HTTP 模块足够；零依赖 = 克隆即跑 |
| 模块规范 | **ESM**（`package.json` 声明 `"type": "module"`） | Node 22 原生支持，语法清晰 |
| 存储 | **文件系统 JSON**（`data/` 目录） | 无数据库依赖；事实包缓存、档案、订单都用 JSON 落盘 |
| 前端 | **原生 HTML/CSS/JS 单页** | 无构建步骤，直接由 Node 服务托管 |
| 天文算法 | **Meeus《Astronomical Algorithms》低精度公式** | 节气、朔望可离线计算；精度足以支撑民用排盘（误差量级见 §9） |
| 解读 | **本地规则模板引擎**（可替换 LLM 适配器） | 保证离线可跑、结果可复现、无幻觉 |

**依赖规则（严格单向，禁止反向依赖）**：
- `core/*` 不依赖任何上层
- `engines/*` 只依赖 `core/*`
- `interpret` / `report` / `commerce` 只依赖 `engines/*` 产出的**事实包**，不得直接调用引擎或自行推算命理事实
- `compliance` 是所有对外文案的**唯一出口**

## 4. 核心数据结构

### 4.1 输入契约

```js
// 八字输入
{
  type: 'bazi',
  calendar: 'gregorian' | 'lunar',   // 默认 gregorian
  year: 1990, month: 5, day: 20,     // 公历或农历年月日
  hour: 14, minute: 30,              // 24 小时制（本地标准时间）
  gender: 'male' | 'female',
  isLeapMonth: false,                // 仅农历输入时有效
  city: '北京',                       // 或 lon/lat
  lon: 116.41, lat: 39.90,           // 可选，优先于 city
  useTrueSolarTime: true             // 是否做真太阳时校正
}

// 六爻输入
{ type: 'liuyao', method: 'time'|'number', question: '...', category: 'career',
  year, month, day, hour, minute, city, numbers: [23, 88] }

// 奇门输入
{ type: 'qimen', purpose: 'wealth'|'career'|'travel'|'negotiate'|'general',
  year, month, day, hour, minute, city }
```

| # | 假设/决策 | 理由 |
|---|---|---|
| D1 | **已实现紫微斗数** | 阶段 2 已落地：五行局表、紫微落宫表（5 局×30 日查表法）、紫府对照表、十四主星双轴布列、生年十天干四化口诀表、辅星安放，均对照公开权威资料并用二十项不变量（含公开例题"农历八月卯时→命宫午/身宫子""甲年四化=廉贞禄/破军权/武曲科/太阳忌"）逐条校验。唯火星/铃星按中州派近似规则，于 `meta.approximations` 标注待校验。 |

| D4 | 时区：**1900 年后中国境内统一按 +8** | 历史时区变动复杂且对排盘影响很小；已在文档与 meta 中声明。 |
| D5 | 奇门采用**时家奇门·转盘·拆补法** | 拆补法规则明确、无置闰歧义，便于确定性实现；局数表用传统"冬至一七四…"口诀。 |
| D6 | 六爻纳甲采用**八宫纳甲歌诀**标准表 | 通用且可验证。 |
| D7 | 解读层默认**本地规则引擎** | 保证离线、可复现、无幻觉；同时预留 LLM 适配器接口，配置 `LLM_ENDPOINT` 后可切换。 |
| D8 | 支付用**本地模拟订单** | 无商户资质，且真实支付涉及合规与风控；模拟订单保留完整状态机，便于后续对接。 |
| D9 | 用神/格局采用**保守规则表 + 弱表述** | 用神判定本身流派分歧大，弱表述既降低争议也降低合规风险。 |
| D10 | 存储用 **JSON 文件** | 零依赖；`data/` 目录下按类型分文件，可直接查看审计日志。 |

## 10. 已知限制

1. 无真实支付、无用户账号体系（本地档案用浏览器 localStorage）
2. 紫微斗数火星/铃星为近似规则（其余主星、四化、大限为本派标准，已校验）
3. 天文算法存在分钟级误差（仅影响交界个案）
4. 解读为规则模板生成，文学性弱于大模型（但可复现、无幻觉）
5. 未做规模化性能优化（缓存为文件级，非分布式）
6. 未做完整国际化/多时区历史校正
