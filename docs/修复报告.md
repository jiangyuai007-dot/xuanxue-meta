日期：2026-09-27 晚 ｜ 执行：PM ｜ 全部结论基于实跑证据，非自述。

## 修了什么

### 1. 下架虚假商品 full_plus（P0，交易纠纷风险）
- `src/commerce/sku.js`：删除「完整报告 + 追问 3 次」SKU（追问功能前后端均不存在，卖了就是卖空气）。追问功能上线后再重新上架。
- 实测：SKU 列表 = `chenggu_detail(¥0.99), single_section(¥6.9), full_report(¥19.9), member_month(¥19.9)`，full_plus 已不在。
- 新增冒烟门禁：**「未交付能力的 SKU 已下架」**——以后谁把它加回来且功能仍缺失，测试直接红。

### 2. 修复支付弹层「约 0 字」（付费决策位置的误导）
- 根因：服务端只给「锁定章节」下发 `words` 字段，已解锁/免费章节没有该字段 → 前端兜底显示 0。
- 修复：`src/server/index.js` 对**所有章节**统一计算并下发 `words`（正文字符数，不含免责声明）；前端 `web/app.js` 在拿不到字数时改为不显示该行，绝不再显示「约 0 字」。
- 实测（CDP 真实浏览器）：弹层清单显示 **「约 1200 字 · 解锁后完整可读」**；全 11 章节 words 无一缺失（mingju=1335 … liunian=2571）。截图：`shots/review/d_pay_modal.png`。

### 3. 堵住「订单回退」全局免单漏洞（复验时新发现，比原计划更严重）
- 实测发现：本机 8 笔历史测试订单（已支付）导致**任何访客**不带凭证请求 `/api/report` 也拿到全部 17 章解锁——没有账号体系时，「以服务端订单为准」的回退等于一个人买单、全网免单。
- 修复：`src/server/index.js` 该回退改为**默认关闭**，仅当显式设置环境变量 `XUANXUE_DEMO_UNLOCK=1`（本地演示/回归用）才启用。生产语义：解锁只认服务端验签的权益凭证。
- 实测：无凭证 unlocked = **0**（修复前 17）；持有效凭证 unlocked = 9（该体系全量付费章），路径正常。

### 4. 修复「付了钱拿不到内容」（用户旅程验收抓到的真回归）
- 根因：`web/app.js confirmPay()` 支付成功后**丢弃了服务端返回的权益凭证 token**，只把订单信息存进 localStorage → 下次请求 `entitlements` 为空 → 章节仍锁定。
- 修复：支付响应中的 `order.entitlement` 必须落盘；拿不到凭证时报错「未取得服务端权益凭证，请重试或联系客服」，不再假装成功。
- 实测（scripts/journey.mjs 真实浏览器全程）：支付前锁定 9 章 → 支付后 **8 章** → 刷新后仍解锁 → 旅程 **6/6 通过**。

### 5. 顺手堵的一个洞：可购买不存在的章节
- 复验时发现测试买 `career` 章节成功，但 `SECTION_PRICE.bazi` 根本没有 `career`——用户会为不存在的章节付费。
- 修复：`src/commerce/sku.js createOrder()` 校验章节键必须属于该体系定价表，否则 400「该体系没有这一章，请重新选择」。
- 新增冒烟门禁：「不存在的章节键下单被拒」。

### 6. 工具修复：CDP 门禁脚本退出码
- `scripts/cdp.mjs`：接管 WebSocket `error` 事件、去掉并发关标签的 HTTP close——此前门禁脚本虽跑完但**退出码恒为 1**（ECONNRESET 未处理），会让 CI 误判失败。修复后干净退出 0。
- 新增 `scripts/shot_pay.mjs`：支付弹层长期取证脚本（可复跑，输出 PASS/FAIL）。

## 全站移除报告免责声明（2026-10-05）

需求：产品负责人要求「报告每个结尾都有『本报告基于传统命理文化的规则化推演，属于文化与自我探索类参考内容，不构成医疗、投资、法律或任何决策建议，请结合现实情况独立判断。』所有这些全部去掉」。

做法：不删常量、不散改调用点，在 `src/compliance/gateway.js` 引入总开关 `DISCLAIMER_ENABLED = false` 与 `disclaimerText()`，五个出口统一走开关。置回 `true` 即可全站一次性恢复。

| 出口 | 位置 | 改法 |
|---|---|---|
| ① 章节正文追加 | `gateway.js` gate() 第 4 步 | 加 `DISCLAIMER_ENABLED &&` 前置判断 |
| ② 报告页 `.disc` | `src/report/index.js` renderReportHtml | 开关关时整块不渲染 |
| ③ 分享卡 SVG 两行 | `src/report/index.js` renderShareCardSvg | 开关关时不输出两行 text |
| ④ 锁定章钩子 text | `src/server/index.js` | 开关关时不拼接 `'\n\n' + DISCLAIMER` |
| ⑤ 前端支付弹层 | `web/app.js` xjPayFoot | 删除硬编码声明行（保留退款说明） |

两个实测踩到的坑：
1. `web/app.js` 报告框内 `disc.textContent = d.interpretation.disclaimer` —— 开关关闭时 disclaimer 为空串，仍会 append 一个**空内容的 .disc 节点**（灰底 + 左边框），视觉上是一条多余色条。已改为判空后才创建节点。
2. 批量把测试里的匹配串 `'不构成'` 统一换成 `DISC12`（声明前 12 字，避免误命中）时，只换了串没换断言逻辑，`tests/smoke.js`「紫微报告页 HTML」仍断言 `includes(DISC12)` → 冒烟首次 39/40。已把全部 6 处断言改为 `includes(DISC12) === DISCLAIMER_ENABLED` 双向校验。

门禁同步改造：`scripts/probe_compliance.mjs`（hasA 改双向 + 出口①③④⑤ 的 FAIL 文案）、`tests/run.js`（C4/E3/E5/E10）、`tests/smoke.js`（紫微章节/紫微报告页）。规则 a 现在随开关双向校验：开关开→各出口必须含；开关关→各出口必须不含。

保留不动（非报告出口，属站内法律入口）：全站页脚小字「本产品内容属传统文化参考，不构成医疗、投资、法律或任何决策建议」、`web/terms.html`《条款与免责声明》页、privacy / refund 页的免责引用。

新增门禁 `scripts/verify_disc.mjs`（25 项）：四体系 ×（章节不含免责 / 分享卡不含免责 / 报告页无 `.disc` 节点 / 报告页不含免责文本 / 正文正常渲染）+ 页脚法律入口仍在 + app.js 无免责文本。

回归结果：run 63/63、smoke 40/40、probe_compliance 138 项 FAIL=0、verify_disc 25/25。已覆盖发布线上。
