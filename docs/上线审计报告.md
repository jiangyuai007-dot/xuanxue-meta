## 二、P0 阻断项（必须修，否则不能上线）

### P0-1 权益可伪造：前端说什么就是什么（收入归零风险）
- 实测：POST `/api/report` 携带 `purchased:[全部章节键]` → **11/11 章节全部解锁**（`preview=false`），零支付。
- 根因：`src/server/index.js` 用前端传来的 `purchased` 数组直接判定已购；已购记录存在浏览器 `localStorage`，用户改一行 JS 即可全解锁。
- 要求：权益判定必须以服务端订单为准；前端传入的凭证需服务端签名/校验（订单号 + 签名，或服务端会话）。

### P0-2 报告页 URL 无任何鉴权（隐私泄漏）
- 实测：仅凭 `/api/report/<id>/html` 即可拿到 **93KB 完整报告**（含姓名无关的精确出生时间、命盘、付费章节）。
- 报告 id 是输入哈希，任何拿到链接的人（转发、浏览器历史、搜索引擎）都能看。
- 要求：报告页访问需一次性 token 或登录态；默认不索引、不暴露完整盘面给未授权者。

### P0-3 服务端无输入校验 + 内部错误信息泄漏
- 实测：`{}` 空输入 → 返回 `Cannot read properties of undefined (reading 'gan')`（内部堆栈原文直接给前端）。
- 实测：`year=1800`（页面限制 1900-2100）、`2月31日` 这类非法日期 → 后端照排不误，静默产出错误命盘。
- 要求：入参强校验（类型/范围/日历合法性），错误统一为用户可读文案，日志侧保留堆栈。

### P0-4 无任何限流 + 每次请求写磁盘（可用性）
- 实测：30 并发 → 26ms 内全部 200，无限流、无熔断、无配额。
- 实测：缓存目录已 **1044 个文件 / 14.9MB** 且无淘汰策略；内存 `reports` Map 无上限。
- 公网后果：一次刷接口即写满磁盘、拖垮内存。要求：IP 级限流、缓存 LRU/TTL 淘汰、内存报告数上限。

### P0-5 法律与资质缺位（法务风险）
- 现状：无隐私政策、无用户协议、无退款/售后说明、无联系方式；付费产品在国内公网部署需 ICP 备案；命理类目在应用商店/平台存在「封建迷信」类合规风险。
- 要求：补齐三份法律文本 + 页脚入口；报告与页面保留「文化娱乐、非决策建议」定位；明确不收集/最小化收集个人信息。

### 仍不可上线的剩余项（需用户/运营决策，非代码）

3. **账号体系**：凭证现存在浏览器本地，换设备/清缓存即丢；跨设备需登录。
4. **HTTPS/TLS 与进程守护**：需反向代理（Nginx/Caddy）+ 证书 + 守护进程（PM2/systemd）。
5. **缓存目录与订单文件**：单机文件存储，多实例部署前需换共享存储。
