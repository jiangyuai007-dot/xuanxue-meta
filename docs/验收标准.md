# 产品级验收标准（PM 验收用，子代理必须自测通过后才准提交）

## 验收工具（必须先跑）
```
node scripts/audit.mjs 8787        # 截图 + 溢出/触控审计，退出码 2 = 不合格
node tests/run.js                  # 55 项单元/端到端
node tests/smoke.js                # 30 项接口冒烟（会自起 8787，注意先停占端口的服务）
```
截图落盘 `shots/`，审计落盘 `.audit.json`。**提交前必须贴出三项结果。**

## A. 移动端（375px）—— 硬性
1. `overflow=0` 且 `elOverflow=0`（无横向滚动、无越界元素）
2. **表单字段值完整可读**：年(4位)/月/日/时/分 的 input 内数字不得被截断显示成 "19.."
3. 触控目标高度 ≥ 36px（button/select/input/label.chk 全部达标；审计的 smallTap 必须为 0）
4. 排盘 → 报告全流程在 375px 下可走通，图表可读、不重叠
5. 顶部导航 tab 横向可滑，当前项高亮清晰

## B. 桌面（1280px）
1. 三栏工作台不塌、不出现意外空白
2. 图表居中、不溢出容器

## C. 商业化闭环 —— 这是本产品的命
1. 锁定章节预览必须有「钩子」：让用户看到"这里有什么"，而不是只看到"需解锁"
2. 点击解锁 → 明确的价格与内容清单 → 支付 → 即时解锁 → **刷新/重进后仍解锁**（持久化，不许内存丢失）
3. 已购章节有可见入口（"我的已购"/订单记录），能重新查看
4. 全流程文案不许出现"模拟/测试/占位"字样对用户可见

## D. 一致性
1. 四个页面顶栏/品牌/配色/按钮/卡片风格统一
2. 空状态、加载中、失败提示三态齐全且样式统一

## E. 质量底线
1. `tests/run.js` 55/55、`smoke.js` 30/30 不得回归
2. 新增能力必须补测试
3. 不许引入第三方运行时依赖（本项目零依赖是架构红线）
4. 合规网关 `gateSections` 必须仍是所有对外文案的唯一出口，任何新文案不许绕过

## 禁止事项
- 禁止改 `src/core/*`（排盘引擎是已验证的地基，动它必须先说明理由）
- 禁止删除或弱化免责声明
- 禁止 `git push` / 外部网络请求
- 禁止引入 npm 依赖
